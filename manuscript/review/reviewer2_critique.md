# Reviewer #2 Critique: "Swedish Parliament Policy Classifier"

## Summary

This work attempts to classify Swedish parliamentary speeches, motions, and votes along a left-right ideological spectrum using a hybrid keyword + embedding + zero-shot NLP pipeline. While the breadth of data sources (speeches, motions, votes, interpellations, written questions) is commendable, I have serious concerns about the methodological rigor, statistical appropriateness, data provenance, and reproducibility of the results presented. Below I detail the major issues that must be addressed before this work can be considered for publication.

---

## 1. Methodological Concerns

### 1.1 Classification Pipeline Validity

The core classification pipeline is a **hybrid of keyword-based rule matching, sentence transformer embeddings, and zero-shot NLI**. There is no clear justification for why this particular combination was chosen, nor any systematic comparison against simpler baselines (e.g., a logistic regression on bag-of-words, or a fine-tuned Swedish BERT). The absence of a **held-out test set with known labels** makes it impossible to evaluate whether the classifier actually measures political ideology or is simply capturing topic- or document-type artifacts.

The "gold labels" appear to be generated by an Ollama LLM teacher model, which is itself unsupervised — raising concerns about circular validation. The self-training loop further amplifies any systematic biases in the teacher.

### 1.2 Ideological Category Definitions

The seven-category ideological spectrum (far_left → far_right) is presented as a fixed ontology. There is no evidence that this taxonomy is appropriate for the Swedish context, nor any sensitivity analysis showing results under coarser or finer granularities. The keyword lists used for rhetorical weight detection are **arbitrary** — no corpus-based method was used to derive them, and no inter-annotator agreement is reported.

### 1.3 Statistical Methods

The statistical testing framework has **fundamental problems**:

- The `_normal_enough()` heuristic attempts to gate between parametric and non-parametric tests, but the logic is ad-hoc. At n ≥ 30, the paired t-test is used unconditionally — while the CLT provides asymptotic normality of the *mean*, it does not guarantee the t-statistic follows a t-distribution for skewed data. A better approach would be to use **bootstrapped confidence intervals** or **permutation tests** throughout.

- **Multiple comparisons are not properly corrected.** The pipeline runs dozens (potentially hundreds) of paired hypothesis tests across party × category × modality combinations. The `apply_bh_correction()` function exists but is not consistently applied. Many reported p-values in the manuscript are uncorrected.

- The sample sizes for some comparisons are extremely small (n=8 parties for some tests). At n < 10, neither the Wilcoxon signed-rank test nor the paired t-test has meaningful power to detect effects. The paper should either pool data across categories or report effect sizes with credible intervals rather than relying on null-hypothesis significance testing.

## 2. Data Provenance and Reproducibility

### 2.1 No Versioned Dataset Snapshots

The analysis relies on parquet files that are **modified in-place** by the incremental update pipeline. There is no mechanism to reproduce the results from a specific date. The raw API data (`data/bulk_datasets/*.zip`) and processed parquet files stored via Git LFS are overwritten on each run. An independent researcher cannot verify the claims because there is no versioned dataset release.

### 2.2 Missing Data Sources

The manuscript claims to analyze speeches, motions, votes, interpellations, and written questions — yet the "classify_interpellations" and "classify_questions" steps report **0 rows processed** (because all IDs are already registered in the shared `classifications.parquet`). It is unclear whether this means (a) these data sources are fully classified, (b) they were never classified and are just being skipped by the de-dup check, or (c) the input parquet files are stale and haven't been updated. The pipeline log is ambiguous.

Furthermore, **betänkande (committee reports)** are downloaded and extracted (`scripts/extract_betankande.py`) but do not appear in the main analysis pipeline. It is unclear why this substantial data source is excluded.

### 2.3 Computational Environment

The repository uses `uv` rather than pip/conda, and while `uv.lock` is present, there is no containerized environment (no Dockerfile, no devcontainer.json). Given the complexity of the dependency stack (torch, transformers, spaCy, sentence-transformers, etc.), this makes reproduction fragile.

## 3. Code Quality

### 3.1 Inconsistent Logging

The codebase uses a mix of:
- `print()` statements (scattered across scripts)
- `logging` module (`scorer.py`, etc.)
- `loguru` (`update_pipeline.py`)
- `sys.stderr.write()` (some scripts)

This makes debugging difficult. The same task is logged differently depending on which file happens to handle it. The AGENTS.md file says "should be using loguru" but this is not enforced.

### 3.2 Monolithic Scripts

Scripts like `classify_speeches_parquet.py` are **over 800 lines long** with global mutable state (`_sigterm_ctx`, `_current_speech_id`), multiple concerns (argument parsing, model loading, classification loop, signal handling, progress reporting, EWMA tracking), and sparse error handling. These should be refactored into smaller, testable modules.

### 3.3 Hard-Coded Paths

Many scripts reference hard-coded paths like `models/rhetorical_weights_best.json`, `data/parquet/speech_classifications.parquet`, `logs/classify_crash.log`. These should be configurable through a single config object or environment variables.

### 3.4 No Type Stubs

The codebase includes `from __future__ import annotations` and uses type hints extensively, but there are no `.pyi` stub files or runtime type checkers (mypy/pyright) configured in CI. Given the complexity, this is a recipe for type-related runtime errors.

---

## 4. Manuscript Concerns

### 4.1 Stale Figure References

At least one figure (`overlay`) fails to regenerate with a `TypeError` (fixed by adding `.dropna()`). Other figures reference "pending" versions. The manuscript's figure pipeline is not reproducible without manual intervention.

### 4.2 Overclaiming

The manuscript uses **causal language** (e.g., "speeches cause subsequent actions," "ideology drives voting patterns") but the analysis is entirely **correlational**. There is no temporal modeling (e.g., Granger causality, cross-lagged panel, or instrumental variables) that would support causal claims.

### 4.3 Missing Effect Sizes

Many claims are supported only by p-values. Cohen's d and Wilcoxon effect sizes are computed in `statistical_tests.py` but are rarely reported in the manuscript text or tables. Effect sizes with confidence intervals should replace or supplement p-values throughout.

---

## 5. Recommendations

**Must address before any resubmission:**

1. **Fix the statistical framework**: Use permutation tests or bootstrapped CIs throughout, consistently apply FDR correction, and report effect sizes with uncertainty intervals.
2. **Create a versioned dataset release**: Tag the exact parquet files used for analysis with a DOI or Zenodo record.
3. **Add a held-out test set**: Report precision, recall, F1 against human-annotated labels.
4. **Containerize the environment**: Add a Dockerfile and CI test that runs `make figures` on a fresh clone.
5. **Justify the category taxonomy**: Provide evidence (corpus analysis, expert survey) that the 7-point left-right spectrum is meaningful for Swedish parliamentary discourse.
6. **Replace null-hypothesis testing with estimation**: Report mean differences and 95% bootstrap CIs rather than p-values for small-n comparisons.
7. **Refactor monolithic scripts**: Split `classify_speeches_parquet.py` into importable, testable modules with a single logging strategy (loguru).

**Should address:**

8. Integrate betänkande data and document why it was excluded.
9. Clarify the classify_questions/classify_interpellations pipeline status.
10. Remove causal language from the manuscript unless causal identification is established.
